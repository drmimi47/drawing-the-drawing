BLINDSPOT — IMPLEMENTATION PLAN
================================================================================
A second-order cybernetics sketching tool where geometry persists only while
observed. Optimized for step-by-step development using generative code agents.


TECH STACK
----------
- TypeScript        — strict typing across geometry graph, mutation engine, API contracts
- React             — UI shell: floating toolbars, mode selector, lock controls, evolution panel
- Zustand           — centralized high-performance state for canvas, tool, and mutation modes
- React Three Fiber — WebGL canvas scene via Three.js; stroke rendering, pin glow, history layers
- WebGL (via R3F)   — custom shaders for metaball influence fields and opacity-layered history
- Vite              — fast HMR dev server, native ESM build
- GitHub            — version control, PR-based workflow
- Vercel            — deployment with Edge Function support for downstream API integrations

NOTE: R3F is the WebGL layer — no raw WebGL boilerplate needed separately.


DESIGN SYSTEM & UX
------------------
CANVAS
  - Infinite, minimalist light-gray background (#F9F9F9)
  - Subtle dot-grid that scales smoothly with zoom level (disappears when zoomed far out)
  - Full 100vw / 100vh app wrapper; no scrollbars

TOOLBARS
  - Floating bottom-center dock: tool selector (Draw / Pan / Lock)
  - Floating top-left: mutation mode selector (Normalization / Rationalism / Hallucination)
  - Clean icons, active-state highlight, smooth hover transitions
  - No heavy chrome — the drawing surface dominates

CURSORS (adaptive, hardware-level swapping)
  - Draw mode:   precision crosshair or pencil icon
  - Pan mode:    open hand (grab) → closed hand (grabbing) during active drag
  - Lock mode:   target/pin icon
  - Mutations in progress: no cursor override — tool cursor persists

INTERACTIONS
  - Keyboard hotkeys for frictionless tool switching (see Cluster J)
  - Spring-loaded feel: tool switches are instant, no modal dialogs

CORE DATA MODEL  (layered — editable graph is the source of truth)
------------------------------------------------------------------
Architecture decision: the editable model is a planar graph of vertices + edges
(a PSLG), NOT a Bezier/spline source of truth. Reasons: every planned feature —
Normalization (snap edge angles), Rationalism (drift vertices to grid), Locking
(per-vertex influence), Lineage (vertex/edge snapshots), and especially
Hallucination (LLM edits a JSON segment list) — operates on segments and shared
vertices. A curve-as-truth model would force a lossy tessellate→operate→re-fit
round-trip on every mutation and make AI edits topologically fragile. Curves stay
an OPTIONAL layer (per-vertex tangents / edge curve descriptors) that always
tessellates down to the polyline graph; this preserves a path to arcs/constraints
later without blocking the segment-based features now.

Three decoupled tiers:
  Tier 1 — Input        Raw pointer samples retained per stroke (re-fit / analysis)
                        RawSample { x, y, pressure, t }
  Tier 2 — Edit model   Planar graph; the SOURCE OF TRUTH for editing/mutations/AI
                        Vertex    { id, x, y }            (position; shared at intersections)
                        PathPoint { v: vertexId, w }      (per-stroke half-width at that vertex)
                        Stroke    { id, color, path: PathPoint[], raw?: RawSample[] }
                        Edge      { id, strokeId, v0, v1 } (derived: consecutive path vertices)
                        Graph     { vertices: Record<id,Vertex>, strokes: Stroke[] }
                        (future-reserved on Vertex: tangentIn/Out; on Edge: curve descriptor)
  Tier 3 — Render       Triangle ribbon, a DERIVED CACHE rebuilt from Tier 2:
                        centripetal Catmull-Rom resample of the path → smooth
                        centerline → variable-width ribbon with round caps.

Pin      { id, x, y, radius }            (Cluster H)
Snapshot { timestamp, graph: Graph }     (Cluster I)

Shared vertices give topology: when stroke B crosses stroke A, one Vertex is
inserted into BOTH paths at the crossing, so the strokes meet at a real node that
mutations can act on. Width lives on the PathPoint (per stroke), position on the
Vertex (shared). Smoothness is a Tier 1/3 concern (retain raw, resample, round
caps) — independent of the editable model, which fixes the post-finalize
faceting caused by raw RDP decimation.

Tool state enum:  'DRAW' | 'PAN' | 'LOCK'
Mutation mode enum:  'NORMALIZATION' | 'RATIONALISM' | 'HALLUCINATION'


MUTATION RULES (implementation detail)
---------------------------------------
VIEWPORT OBSERVER
  - Orthographic camera bounds = viewport AABB, recalculated on every pan/zoom event
  - On pan-end or zoom-end: diff currently visible edges vs. previous frame
  - Edges crossing OUT: record exitedViewportAt = Date.now()
  - Edges crossing IN:  compute timeOutside = now - exitedViewportAt; queue for mutation

TIME DECAY
  - mutationMagnitude = clamp(timeOutside / DECAY_MAX_MS, 0, 1)
  - DECAY_MAX_MS = 30 000 ms default (tunable constant)
  - lockInfluence per vertex (0–1) reduces magnitude: effectiveMag = mag * (1 - lockInfluence)

NORMALIZATION — IMPLEMENTED (local, procedural)
  - Per re-entering edge: measure angle → snap to nearest 15° increment if within threshold
  - Detect near-parallel neighbors (within 10°) → apply small attractive force toward shared angle
  - Force relaxation pass on adjacent vertices to prevent tearing at shared joints
  - Operates edge-by-edge; no opinion on global composition

RATIONALISM — DEFERRED (global, procedural)
  - Seed a constraint field from existing geometry; vertices drift toward grid intersections
  - Short dangling edges extend toward adjacencies; near-closed polygons close fully
  - Stub only — selecting this mode is a no-op in the current build

HALLUCINATION — DEFERRED (LLM, multi-modal)
  - Serialize visible graph → JSON segment list → POST to Anthropic API (claude-sonnet-4-6)
  - Parse returned geometry → diff against current graph → animate new edges in over 1–2s
  - Vercel Edge Function proxies the call (API key stays server-side)
  - Stub only — api/hallucinate.ts returns { segments: [] } placeholder


LOCKING MECHANISM
-----------------
- Pins placed by shift+click when tool is 'LOCK'
- Influence per vertex: influence_i = clamp(1 - dist(v, pin)² / pin.radius², 0, 1)
- Multiple pins: totalInfluence = clamp(sum of all influences, 0, 1)
- Visualized as soft glowing red rings (influence.frag shader, smooth radial falloff)
- Effective mutation magnitude: effectiveMag = baseMag * (1 - totalInfluence)


EVOLUTIONARY LINEAGE
--------------------
- On every mutation event: deep-clone current graph → push Snapshot to history array
- History is invisible during normal session
- On reveal: render all snapshots as stacked Three.js LineSegments layers
  - opacity = lerp(0.05, 1.0, index / total)  — oldest = faintest, newest = darkest
  - All layers render simultaneously (light-table effect, not animation)
- "Export Artwork" button: capture canvas via Three.js preserveDrawingBuffer → PNG


IMPLEMENTATION CLUSTERS
-----------------------
Execute clusters sequentially. Each must compile and pass its verification goal
before moving to the next.

CLUSTER A — Project Scaffold & Canvas Viewport
  [ ] Initialize Vite + React + TypeScript app (npm create vite)
  [ ] Install: three, @react-three/fiber, @react-three/drei, zustand, lucide-react
  [ ] Set up Tailwind CSS or a minimal global CSS reset for layout
  [ ] Build 100vw / 100vh app wrapper; mount R3F Canvas component
  [ ] Configure OrthographicCamera for 2D top-down world-space coordinates
  [ ] Implement persistent infinite dot-grid background: tiled plane scaling with zoom,
      fading out when zoomed far out, always light and non-distracting
  [ ] Stub floating bottom-center toolbar overlay (empty, just positioned correctly)
  [ ] Connect GitHub repo; wire Vercel for preview deploys on every push
  * Verification Goal: App compiles with zero errors, renders a full-screen light-gray
    workspace with subtle dot grid, shows an empty floating toolbar, and Vercel
    preview URL is live.

CLUSTER B — Freehand Drawing Pipeline
  [ ] Initialize Zustand store with toolMode: 'DRAW' | 'PAN' | 'LOCK' = 'DRAW'
  [ ] Pointer event capture: pointerdown / pointermove / pointerup → raw point array
      (only when toolMode === 'DRAW')
  [ ] Render a live Three.js Line object following the mouse path during drag
  [ ] On pointer-up: apply Ramer-Douglas-Peucker simplification (geometry/simplify.ts);
      commit simplified polyline as a completed stroke
  [ ] Variable line weight from PointerEvent.pressure; fallback to constant if 0
  [ ] Cursor: crosshair when toolMode === 'DRAW'
  [ ] Stroke color picker swatch in toolbar (basic, no heavy styling yet)
  [ ] Undo: Ctrl+Z removes the last completed stroke
  * Verification Goal: Freehand lines render instantly with no jitter. Pressing Undo
    cleanly removes the last stroke. Pressure produces thicker lines on a tablet.

CLUSTER C — Infinite Canvas Navigation
  [ ] Pan: spacebar + left-drag OR middle-mouse drag translates OrthographicCamera
  [ ] Zoom: scroll wheel zooms toward cursor world-space position (no cursor drift)
  [ ] useViewport hook: computes and exposes viewport AABB on every camera change
  [ ] Cursor: open hand for PAN mode, closed hand during active drag
  [ ] Tool switching: spacebar held = temporary PAN override; released = back to DRAW
  [ ] No jitter or drift artifacts during simultaneous pan + zoom
  * Verification Goal: Panning and zooming feel identical in responsiveness to Miro
    or Figma. Holding space temporarily switches to pan without disrupting draw mode.

CLUSTER D — Geometry Graph Compilation & Intersection Engine (enriched model)
  [ ] Define Tier 1/2 types in types/geometry.ts (RawSample, Vertex, PathPoint, Stroke, Edge, Graph)
  [ ] Retain raw pointer samples per stroke (Tier 1); stable IDs on vertices/strokes
  [ ] On stroke completion: RDP-simplify, build vertices + path, insert into graph store
  [ ] Intersection engine: test new stroke vs. all existing edges; at each crossing insert
      ONE shared Vertex into both paths (splitting both), with per-stroke interpolated width
  [ ] Smooth rendering (Tier 3): centripetal Catmull-Rom resample + variable-width ribbon
      with round caps; mesh is a derived cache rebuilt from the graph
  [ ] graph.ts API: addStrokeToGraph(), eraseGraphCapsule(), resolveStrokePoints(), deriveEdges()
  [ ] Eraser operates on the graph (rebuilds affected strokes; orphan vertices dropped)
  * Verification Goal: Crossing two strokes inserts a shared node referenced by both
    (visible in the graph), finalized strokes stay smooth (no faceting), and a graph
    intersection unit test passes. (Self-intersection within one stroke deferred.)

CLUSTER E — Continuous Viewport Edge Observer
  [ ] On pan-end, zoom-end, and stroke completion: run edge-vs-AABB test for all edges
  [ ] Edges exiting viewport: stamp exitedViewportAt = Date.now() on the edge record
  [ ] Edges re-entering viewport: compute timeOutside, clear exit stamp, push to
      pending mutation queue
  [ ] Debug toggle (dev only): highlight out-of-bounds edges in muted red/transparent
  * Verification Goal: Panning lines off-screen and back on-screen correctly tracks
    how long each edge was hidden. Debug mode visually confirms out-of-viewport edges.

CLUSTER F — Normalization Mode (full implementation)
  [ ] useMutation hook: consumes pending mutation queue from viewport observer
  [ ] mutationMagnitude = clamp(timeOutside / DECAY_MAX_MS, 0, 1); DECAY_MAX_MS = 30000

  [ ] normalize.ts: per re-entering edge, detect near-parallel neighbors (threshold 10°),

  [ ] Lerp mutated vertices to new positions over ~500ms
  [ ] Normalization is the default active mutation mode
  [ ] Tune DECAY_MAX_MS and snap threshold until behavior matches the concept doc
  * Verification Goal: Drawing rough boxes, panning them off-screen for ~15 seconds,
    then panning back shows lines self-aligning toward angular coherence. The effect
    scales with time out of view.

CLUSTER G — Mutation Mode State Machine (skeleton)

CLUSTER H — Lock Pins & Radial Influence Fields

OPEN QUESTIONS / DECISIONS TO REVISIT
--------------------------------------
- Intersection detection: brute-force O(n²) is fine for sketch scale; upgrade to
  Bentley-Ottmann sweep-line if performance degrades on large drawings
- Dot-grid implementation: shader-based (most performant) vs. instanced mesh tiles —
  decide during Cluster A based on zoom-scaling behavior
- Wacom full SDK (pressure curves, tilt): requires browser plugin; treat as an
  enhancement over the standard PointerEvent.pressure path already in Cluster B
- DECAY_MAX_MS = 30 000 ms is a starting value; tune during Cluster F
- History memory cap of 200 snapshots: revisit if export fidelity requires more states
- Rationalism grid spacing: infer from stroke density vs. fixed user-defined grid —
  decide when implementing that mode
