Onboarding reference for collaborators and LLM coding agents: intent, architecture,

Last updated: 2026-06-05 (geodesic department fields; room editing + multi-grid room

WHAT IT IS
----------
Gradia is a web sketch-to-plan ideation tool for architects/urban designers — a
precision VECTOR environment (not a diffusion image renderer). The designer keeps
authorial control over every segment; an LLM is a downstream co-resolver (Phase 2).

It is built as a CONSTRAINT-ACCUMULATING PIPELINE of layers. Constraints only tighten
as you move down the stack; you can revisit any layer non-destructively, and derived
geometry (rooms) re-flows automatically.

----------

THE LAYER PIPELINE (the core workflow)
--------------------------------------
The right-panel Layer Hierarchy is the app's spine (LAYER_ORDER). Switching a layer
sets its default tool and gates which tools are enabled (Ribbon LAYER_ENABLED_TOOLS);
each board remembers its own layer state. Sequential unlock (maxLayerReached).

  0 CONTEXT      Choose a substrate: MAP (Mapbox underlay, sets real-world scale) or
                 BLANK (white sheet + optional grid). Pan only.
  1 LOT BOUNDARY Trace the closed lot ring (the master work area). Optional target
                 area (advisory delta + area lock). A structural GRID is fit to the
                 lot edges here; drawing open polylines = SEAMS that split the lot into
                 regions, each with its own best-fit grid orientation (geometry/lotGrid).
  2 CIRCULATION  Draw hallway centerlines, each tagged MAIN or MINOR (per-tier widths).
                 MAIN = hard wall (splits the lot, blocks department fields + rooms);
                 MINOR = permeable (fields/rooms flow across, hallway carved out at the
                 end). Bands cached as ring arrays; point-in-any-band keep-out.
  3 DEPARTMENTS  Drop program "pins" (soft fields). Each is placed center → TYPE popup
                 → drag radius. The type also seeds a GRAIN. See DEPARTMENT FIELDS below.
  4 ROOMS        Parametric: each department subdivides by GRAIN (open-plan ⟷ cellular).
                 Lock rooms you like; the rest reflow around them. See ROOMS below.
  6 GENERATE     Phase 2 (deferred) — LLM co-resolves the constrained sketch.

  PARKED: the standalone INTENT layer (abstract Density/Pedestrian/SQF/Landuse pins that
  only fed the deferred LLM) is removed from the navigator — "intent" now lives inside each
  department as its GRAIN, which drives rooms directly with no model call. The intent code
  (intentSerialization, metaballField, MetaballOverlay, IntentPin type/store slice) stays
  DORMANT for a future Generate pass; re-add the layer row in RightPanel LAYERS to revive it.

HARD vs SOFT constraints: HARD = lot boundary + MAIN corridors (never violated).
SOFT = department fields overlap freely; MINOR corridors permeable; a pin is a fuzzy
intent, so rooms may shift/stretch off the exact pin for a clean layout.


DEPARTMENT FIELDS (layer 3)
---------------------------
A Department = { id, name, x, y, radius, color, deptType?, targetSqf?, roomCount?, grain? } —
a soft Wyvill field, hard-masked to the lot ∩ ¬MAIN-corridors.

- PROGRAM TYPES (types/geometry DEPARTMENT_TYPES/_META): placing a department picks one
  of 10 office programs from a popup (DepartmentMenu, mirrors IntentPinMenu); the type
  sets the default name + color + GRAIN (DEPARTMENT_META.defaultGrain). CORE (grey #9ca3af)
  and MECHANICAL (black #111111) are service types whose color is FIXED
  (FIXED_COLOR_DEPT_TYPES — setDepartmentColor + the panel swatch refuse to recolor them)
  and whose grain is 0 (monolithic).
- GEODESIC FIELD (geometry/departmentField.ts, buildDepartmentField): influence falls
  off by SHORTEST PATH THROUGH the lot (bounded Dijkstra over a coarse grid, blocked by
  boundary + MAIN corridors), NOT euclidean distance — so fields MORPH around corners
  and fill concave nooks with no sightline seams (replaced the old euclidean + line-of-
  sight shader). All departments blend into ONE RGBA texture on the CPU (dilated under
  corridor bands), sampled by a trivial shader. Rebuilds on any dept/boundary/MAIN
  change incl. live drag. Diagnostics (departmentAreas.ts): per-dept Core (exclusive) vs
  Max (incl. overlap) SQF + lot coverage %.
- VISIBILITY: full color + gradient on the Departments layer; magenta back-reference
  dots on Circulation; hidden elsewhere.
- ROOM LABELS (RoomsOverlay): each room is labelled with its department-TYPE INITIALS
  (initialsOf, e.g. Open Office → "OO") and a small floor-area figure underneath; on the
  Circulation layer only the initials show, in light magenta (matching the ghost walls).
  Labels are drei <Html> (pointerEvents off) and skipped on rooms too small for legible text.


ROOMS (layer 4) — generateRooms() in geometry/rooms.ts
------------------------------------------------------
Derived state: re-generated on ENTRY to the Rooms layer (cascade) and on any room-affecting
edit, from boundary + circulation + departments — so upstream edits re-flow rooms
automatically. Room = { roomId, parentDeptId, polygon, areaSqf, isLocked }.

  GRAIN (the primary control): each department carries grain ∈ [0,1] (0 = open-plan → few
    large rooms, 1 = cellular → many small). generateRooms derives the EFFECTIVE count from
    the department's actual cell area ÷ a grain-implied target room area (grainToTargetArea:
    ~2500→120 ft² with a map scale, else tied to the grid module; geometric interpolation,
    capped GRAIN_ROOM_CAP=48). So a bigger department at the same grain gets more rooms.
    Set via the panel slider (setDeptGrain). Typing an explicit N (setRoomCount) overrides
    grain for that department; both clear the other.
  SEEDING: entering the layer defaults any department with no grain/count yet to
    DEFAULT_ROOM_COUNT=6 rooms (a fixed dev/testing default) so rooms appear immediately;
    dragging the grain slider then hands control to grain. (Type defaultGrain is still used
    for the slider's displayed starting position.)
  UNLOCK GATE: the Rooms layer (and later) unlocks once department gradients cover ≥ 85%
    of the lot infill (DEPT_COVERAGE_MIN = 0.85).
  PASS 0  pieces = lot ∖ MAIN-corridor bands (turf difference; endpoints extended past
          the boundary for a clean cut). Each department binds to the piece containing
          its pin.
  PASS 1  ORTHOGONAL GUILLOTINE: recursively bisect each piece among its departments
          with straight, grid-snapped cuts (area ∝ weight = radius²) → one cell per dept,
          100% fill, no overlap. Each cut uses the LOCAL grid frame at the cut (orientAt) so the
          border between two departments aligns to the grid WHERE THEY MEET (no harsh diagonal
          across a seam), and it runs along the axis the departments are most SPREAD on (siteSpread)
          so one clean grid line separates them; a nearby MAIN hall instead forces cuts ⟂ the hall.
  PASS 2  LINEAR STRIP SLICER: each dept cell → N equal-area rooms cut along a SINGLE grid
          axis (no recursive axis-alternating, so rooms never rotate into landlocked
          orientations). The orientation is chosen by QUALITY (chooseStripSlicing): both grid
          axes are sliced and SCORED (scoreStripSet — rewards hitting the target N, equal room
          areas, low skinniness/aspect); the better option wins, so rooms never come out skinny
          just to follow a heuristic. On a near-tie the corridor-parallel axis (corridorAxisChoice)
          breaks it, so fingers still front the desired circulation. Strip count is capped to the
          min room width (a target N — fewer, fuller rooms beat slivers). linearStripSlice().
          MULTI-GRID CLUSTERING: if a dept cell straddles >1 grid region (the user drew
          seams giving regions different orientations), it gets ONE CLUSTER PER REGION,
          each sliced along its own grid; the room count is split by area (allocateCounts,
          ≥1 per region). sliceDeptAcrossRegions(). Robustness: each region part remembers
          its frame (a single-region cell slices in ITS region's frame, not orientAt(center)
          which returns the whole-lot orientation in the seam gap); intersect is retried with
          cleaned coords (robustIntersect) so a region isn't silently dropped; and the leftover
          (seam band + any dropped region chunk) is reassigned to the region it actually sits in
          — recovering a whole region as its own cluster — so orientations never get crossed.
  PASS 3  MINOR corridors boolean-subtracted from rooms (a crossing hallway splits a room).
  PASS 4  sliver absorption: tiny/thin rooms merge (turf.union) into the best adjacent room,
          but NEVER across grid orientations (a merge whose neighbor sits in a differently-
          oriented seam region is rejected) — so a merged room never mixes two grid directions
          into an arbitrary diagonal. orientAt falls back to the NEAREST region's frame for a
          point in the thin seam gap (not the whole-lot orientation), so seam-adjacent rooms are
          judged in their real grid.

ROOM LOCKING (progressive "complete by accretion"): click a room on the Rooms layer to
freeze it (RoomsOverlay onClick → toggleRoomLock; locked rooms render solid with a heavier
edge). regenRooms() (drawingStore) keeps every locked room verbatim AND feeds them to
generateRooms as KEEP-OUTS (lockedRooms param, subtracted from pieces like MAIN bands) so
unlocked rooms reflow AROUND them. Toggling a lock does NOT reflow — only the next grain/
count/department edit does. RoomControls shows a "% locked / Complete" bar + Unlock-all.

WALL ERASING (Erase tool on the Rooms layer, the DEFAULT tool on entry): contact over the wall
between ANY two adjacent rooms deletes it — the two MERGE into one (geometry/roomMerge.
mergeRoomsAtWall via store.eraseRoomWallAt). The survivor keeps the LARGER room's department (so a
department-border wall erases too, the bigger zone absorbing the smaller) and every affected
department's count is re-pinned. Coordinates are truncated before the union so a hairline float gap
on a shared edge still merges. Won't erase an outer/boundary wall, a corner-only touch, or a locked
room. (The Lock tool, not Erase, toggles room locks.)

ROOM EDITING (Edit tool on the Rooms layer): drag room CORNERS by hand (geometry/
roomEdit.ts). The whole welded joint moves (shared walls stay shared); T-junction
neighbors slide so no gaps open; corners snap to neighbor walls / corridor borders /
the lot boundary, clamp inside the lot, and reject self-intersection or overlap. Edits
are transient (overwritten on the next regeneration).


EDIT (VECTOR) TOOL — what it edits depends on the active layer
--------------------------------------------------------------
geometry/editTargets.getEditTargets selects the draggable set on the ACTIVE board:
  Lot Boundary → ring vertices · Circulation → centerline vertices · Departments → pin
  centers (move the whole zone) · Rooms → room corners (weld drag, above) · Intent → pin
  centers · other → planar-graph vertices.
Graph/boundary/circulation anchors snap to nearby geometry (excluded from snapping to
themselves); Shift constrains to H/V. One undo step per drag. Leaving the tool re-trims
circulation back inside the lot.

GOTCHA (fixed 2026-06-05): drei <Html> ignores its `pointerEvents` prop in non-transform
mode — a centered label (e.g. a department name on its pin) silently swallowed the click
and blocked the Edit tool. Fix = also pass `style={{ pointerEvents: 'none' }}`.


DATA MODEL (source of truth)
----------------------------
All sketch geometry is a Planar Straight-Line Graph (PSLG); renders are a derived cache.
  Graph        { vertices: Record<id,{id,x,y}>, strokes: Stroke[] }   single source
  Stroke       { id, color, path: PathPoint[], raw?, straight?, strokeWidth?, lineStyle? }
  Boundary     { ring: {x,y}[], isClosed?, targetSqf? }               the lot
  CirculationPath { id, centerline: {x,y}[], width, tier:'MAIN'|'MINOR' }
  Department   { id, name, x, y, radius, color, deptType?, targetSqf?, roomCount?, grain? }
  Room         { roomId, parentDeptId, polygon: {x,y}[], areaSqf, isLocked }
  IntentPin    { id, x, y, radius, intentType }
  LockPolygon  { id, points: {x,y}[], featherRadius }
  TextLabel / Underlay / lotGridSeams: {x,y}[][] …
  CanvasEntry  { id, origin:{x,y} } + CanvasDoc (one board's whole document: geometry +
               per-board layer/pipeline state). HistoryEntry snapshots the WHOLE world.

Coordinates: origin (0,0) at the CENTRAL board's page center, y UP. All geometry is in
ABSOLUTE world coords (renders at its board with no transform); only page furniture
(sheet/grid/underlay) sits in a <group position={origin}>. Export flips y:
fx = x + W/2, fy = H/2 − y. metersPerWorldUnit (null until a Mapbox projection calibrates
it) converts world area → ft².


MULTI-BOARD (design-option "branches")
--------------------------------------
The workspace holds several boards laid out spatially as neighboring options. The ACTIVE
board's CanvasDoc IS the live store; inactive boards are read-only snapshots
(inactiveCanvasDocs) rendered at their offsets (InactiveCanvases). Hover an edge midpoint
→ "+" spawns a neighbor (duplicate = deep-copy + shift; or blank). Each board keeps its
own layer memory. Undo/redo is ONE global timeline over the whole world.


RENDERING & INTERACTION
-----------------------
Strokes: Catmull-Rom resampled centerline → uniform-width triangle ribbon (round caps);
polylines use sharp miters. Lineweight/style live on the Stroke; dashed/dotted walk the
centerline by arc length and the same dashArray() drives SVG/PNG/PDF export. RibbonMesh
recomputes its bounding sphere on geometry change (stale-sphere cull fix).
An invisible viewport-following InteractionPlane (useFrame) receives all raycasts, giving
world-space e.point.x/y that survive pan/zoom — the same coords every tool reads.


SNAPPING ENGINE (CAD object-snap)
---------------------------------
spatialIndex.ts — SpatialGrid (64-unit hash) indexes every VERTEX and edge MIDPOINT;
edges are bucketed into every cell their segment traverses (supercover) so long walls
snap along their whole length. Incremental: a vertex drag re-buckets only that vertex +
its incident edges; topology changes rebuild (gated by graph.strokes reference change).
nearest() returns vertex-over-midpoint within SNAP_THRESHOLD_PX(8)/zoom.

Polyline (usePolyline) runs a priority matrix, first hit wins, writes activeSnapGuide:
  Endpoint > Midpoint > Intersection > Perpendicular > Parallel > Extension > Tracking
  (O-TRACK) > Edge. snapMath.ts holds the pure 2D math. SnapGuideOverlay renders screen-
  constant CAD guides (green glyphs / dashed alignment tracks). Vector Edit reuses
  nearest() + the legacy blue SnapIndicator. Master toggle: snappingEnabled (F3 / Ctrl+G).
Circulation Polyline also snaps to the lot grid (nodes/lines/boundary) so paths stay
parallel/perp to the structural grid.


INTENT FIELDS (on the ROOMS layer) & LOCKS
------------------------------------------
The Intent Pin tool unlocks ONLY on the Rooms layer (Ribbon gate) — it paints metaball-like
fields over the finished floorplan. Two types for now: DENSITY (purple) and OPENNESS (teal)
(types/geometry INTENT_TYPES/_META). Pins are per-type Wyvill fields; the GPU MetaballOverlay
streams them via a DataTexture and blends overlaps by concentration (IntentFieldView renders the
field + per-type markers + labels + the hover IntentConcentrationGrid on the Rooms layer).
intentSerialization.ts builds a per-vertex/region intentMix payload (density/openness) — dormant
Phase-2 scaffolding (not yet wired into room generation). LockPolygons mark fixed regions
(interior distance field, lockInfluenceAt) that gate Normalize. (Distinct from per-ROOM locking.)

NORMALIZE (selection-scoped, explicit): right-click a selection → "Clean up" slider.
normalizeStroke() fits line / circle (Pratt) / triangle / rectangle (OBB) per stroke;
lock influence scales each vertex's move. No multi-stroke or ellipse fitting yet.


IMPORT / EXPORT / MAP
---------------------
Image/PDF import → raster Underlay (aspect-fit centered; page frame never resized).
Export SVG / PNG (2×) / PDF (active board only). Mapbox overlay is lazy-loaded; Turf
live measurements; live scale calibration → metersPerWorldUnit. VITE_MAPBOX_TOKEN from
.env (git-ignored); style URL hardcoded in MapView (swap for a Studio style).


PHASE 2 — LLM GENERATE (deferred)
---------------------------------
Serialization is ready (intentSerialization, lockInfluenceAt, geoScale). To activate:
wire api/generate.ts (Vercel Edge Function → Anthropic), encode LOCKED/TRANSITION/OPEN +
intentMix in the system prompt, and merge returned vector segments back into the PSLG
(reviewable Accept/Reject). No raster ever.
