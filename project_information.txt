WHAT THIS PROJECT IS
--------------------
Metaball Sketch is a web-based sketch-to-plan ideation tool for architects and
urban designers. It is NOT a diffusion-based image renderer. It is a precision
vector drawing environment where the designer retains fine-grained authorial
control over every line segment, and an LLM is used as a downstream co-resolver —
not a first-pass guesser.

The core workflow is linear but non-modal:

  IMPORT → SKETCH → NORMALIZE → PIN → GENERATE (Phase 2, deferred)

At each stage the designer can return to any prior stage without destructive loss.
The graph is always editable; generation emits vectors back into the same graph.

The tool is designed to outperform raw AI image generation for architectural
ideation because the designer spatially encodes programmatic intent through Pins
before generation runs. Without this spatial metadata the LLM has no finer
resolution of intent than a generic text prompt — the Pins are what make the
output controllable and site-specific.

DATA MODEL (Source of Truth)
----------------------------
All geometry is a Planar Straight-Line Graph (PSLG). Renders are a derived cache
— never the source of truth.

  RawSample    { x, y, pressure: 0, t }              pointer stream (pressure ignored)
  Vertex       { id, x, y }                           shared at stroke intersections
  PathPoint    { v: vertexId, w: number }             per-stroke half-width reference
  Stroke       { id, color, path: PathPoint[],
                 raw?: RawSample[], straight?: bool } ordered path through vertices
  Edge         { id, strokeId, v0, v1 }               derived from strokes
  Graph        { vertices: Record<id,Vertex>,
                 strokes: Stroke[] }                  single source of truth
  LockPolygon  { id, points: {x,y}[], featherRadius } lock region (rectangle)
  IntentPin    { id, x, y, radius, intentType }       spatial prompt pin
  TextLabel    { id, x, y, text, color, size }        free-floating annotation
  Underlay     { src, opacity, pixelWidth, pixelHeight,
                 x, y, width, height }                raster import with own transform
  Snapshot     { graph, lockPolygons, intentPins,
                 textLabels }                         undo/redo unit

World coordinate system: origin (0,0) at page center, y-axis up, right-handed.
Export flips y: fx(x) = x + W/2, fy(y) = H/2 - y (top-left origin, y down).

The page sheet is an INDEPENDENT world frame: its size (pageWidth/pageHeight,
default 1080×720) is NEVER altered by imports. setPageSize() controls it
explicitly (re-fits any active underlay). An imported asset becomes an Underlay
carrying its own placement transform (centered, aspect-fit to 92% of the page
frame), so assets can be swapped without disturbing the coordinate system.

A real-world scale (metersPerWorldUnit) is held in the store: null until
calibrated by the active Mapbox projection, then updated live on every map
move/zoom via Web Mercator ground resolution math.


RENDERING PIPELINE
------------------
Three tiers, rebuilt from the graph on demand:

  Tier 1 — Raw samples:  stored on Stroke for future re-analysis
  Tier 2 — Graph:        Vertex + PathPoint source of truth
  Tier 3 — Mesh:         centripetal Catmull-Rom resampled centerline →
                         uniform-width triangle ribbon (averaged-tangent normals,
                         round end-caps, 16-step half-disk fans)

Strokes are UNIFORM thickness (pressure sensitivity deliberately removed).
Polylines use buildPolylineRibbon — sharp miter/bevel corners, no spline.
An invisible viewport-following InteractionPlane (useFrame resizes it each tick)
receives all raycasts, giving world-space pointer coords that survive pan/zoom.

Lineweights & line styles (drafting hierarchy, improvements C3): styling lives on
the Stroke (the persistent drawable), NOT on derived Edges — deriveEdges()
regenerates edges every call, so they cannot retain metadata. A Stroke carries
optional strokeWidth (world units; falls back to 2× path half-width) and lineStyle
('solid' | 'dashed' | 'long-dash' | 'dotted'; absent ⇒ solid). The active pen
(store.baseWidth + store.lineStyle, set via the toolbar Pen dropdown — LINEWEIGHTS
presets Fine/Standard/Bold/Thick + the four styles) is stamped onto each new stroke
at commit. buildStrokeGeometry() routes solid strokes straight through the smooth
or polyline ribbon builder; for dashed/dotted it walks the centerline by cumulative
arc length (dashArray() returns [on, off] in WORLD units, proportional to width so
the pattern stays balanced at any weight and zoom), interpolating a boundary point
at each dash edge, builds one ribbon per "on" run, and merges them into one mesh.
The SAME dashArray() drives the SVG (stroke-dasharray), PNG (ctx.setLineDash) and
PDF (setLineDashPattern) exporters, so screen and file output match. Style fields
are preserved through erase and lasso/lock re-segmentation so they survive editing.


SPATIAL INDEX & SNAPPING ENGINE
---------------------------------
src/geometry/spatialIndex.ts — SpatialGrid: a uniform spatial hash grid (64-unit
cells). Two snap target types are indexed:

  VERTEX   — every graph vertex. Because the PSLG inserts a shared vertex at every
             stroke crossing, this automatically covers intersections, endpoints,
             and any manually placed node — no separate intersection index needed.
  MIDPOINT — the midpoint of every derived edge (one per consecutive PathPoint pair
             in each stroke). Computed as (v0 + v1) / 2 at index time.

Storage: the grid stores topology + position (not pre-baked SnapPoints), so it
can be edited incrementally. String-keyed Maps key on "cx:cy" = floor(coord/cell):
  cellVerts   cellKey -> Set<vertexId>   verts whose position lands in the cell
  cellMids    cellKey -> Set<edgeKey>    edges whose midpoint lands in the cell
  vertexPos   vertexId -> {x,y}          live positions
  vertexCell  vertexId -> cellKey        reverse lookup (a point is in one cell)
  edges       edgeKey  -> [v0,v1]        endpoint ids
  edgeMidCell edgeKey  -> cellKey        reverse lookup for midpoints
  vertexEdges vertexId -> Set<edgeKey>   adjacency (moved vertex -> its midpoints)
Query scans a (2R+1)² block of adjacent cells (minCx..maxCx × minCy..maxCy),
touching only the cells that can possibly hold a point within radius R — O(1)-ish
vs. O(n) full scan. For typical SNAP_THRESHOLD_PX/zoom ≈ 8–40 world units and
cell=64, the query block is 1–4 cells in each axis. SnapPoints are materialized
lazily, only for the winning candidate, so per-query allocation is ~zero.

Lifecycle (incremental, improvements C2): the grid is no longer wiped and rebuilt
on every mutation. The drag hot path (setVertexPositions) calls grid.moveVertex
per moved vertex, which re-buckets just that vertex and the midpoints of its
incident edges (O(incident) cells) IN PLACE — so dragging one vertex among
thousands stays 60 FPS. Topology changes still rebuild from scratch, routed
through one seam: setVertexPositions preserves the graph.strokes array reference,
while every topology-changing action (stroke commit, polyline finish, erase,
lasso/lock segmentation, undo, redo, clear) produces a NEW strokes array. The
Zustand subscribe() therefore rebuilds only when state.graph.strokes !==
prev.graph.strokes — an O(1) test that skips the rebuild for position-only moves
(already indexed incrementally) yet auto-covers any edge-set change with zero
per-action boilerplate. Incremental methods: addVertex / moveVertex /
removeVertex / addEdge / removeEdge; empty buckets and dead adjacency sets are
pruned on removal so no stale ids linger.

nearest(x, y, radius, exclude?) query:
  - Scans overlapping grid cells, maintains two separate best candidates:
    bestVertex (closest VERTEX within r²) and bestMid (closest MIDPOINT within r²).
  - Returns bestVertex if found, otherwise bestMid — VERTEX always takes priority,
    even when a midpoint is geometrically closer (endpoint snap is the stronger
    intent; mirrors AutoCAD/Revit snap priority).
  - exclude: Set<vertexId> — skips any target whose vid (VERTEX) or either edge
    endpoint (MIDPOINT) is in the set. Used by Vector Edit so a dragged vertex
    cannot snap to itself or to midpoints of its own edges.

Snap threshold: SNAP_THRESHOLD_PX = 8 (screen pixels) ÷ camera.zoom → world
units. Converts the activation radius into world space so the snap zone stays
visually constant as the user zooms in or out.

Active tools:
  Polyline (usePolyline.ts) — probes the index on every pointer move (showing
    the indicator before any vertices are placed) and on every click. If a target
    is within threshold the cursor locks exactly to it; otherwise Shift-ortho
    applies if held. Object snap takes priority over Shift-ortho.
  Vector Edit (useVectorEdit.ts) — probes on every pointer move while dragging a
    vertex, excluding that vertex and its own edges via the exclude set. Applies
    the snapped position to setVertexPositions so connected strokes update live.

SnapIndicator (components/Canvas/SnapIndicator.tsx):
  A lineLoop built once as a unit outline (half-extent = 1) and rescaled by
  HALF_PX (6px) / camera.zoom each frame via useFrame. Screen-constant physical
  size regardless of zoom level. Two shapes:
    SQUARE  (□) — 4-vertex lineLoop — for VERTEX / endpoint targets
    TRIANGLE (△) — 3-vertex lineLoop — for MIDPOINT targets
  renderOrder 40, depthTest false, frustumCulled false — always on top.


ISOLATED METABALL INTENT FIELD SYSTEM
--------------------------------------
src/utils/metaballField.ts — All math uses the Wyvill soft-object falloff:
  potential = (1 - d²/r²)³   for d < pin.radius,  else 0

  evaluatePinField(x, y, type, pins):
    Filters to the targeted IntentType only (strict per-type isolation — a
    Density pin NEVER bleeds into the Pedestrian field). Sums Wyvill potentials.

  getIntentConcentration(x, y, pins) → { total, fields, mix }:
    Runs evaluatePinField for all 4 types. total = sum. mix = normalized ratios
    (sums to exactly 1 where total > 0 — 100% of local planner intent allocated).

  getRegionConcentration(minX, minY, maxX, maxY, pins) → IntentConcentration:
    3×3 supersample of a cell, averages absolute fields before taking ratios.
    Yields the true area-weighted composition (same as what the LLM reads per
    region). Averaging fields-then-dividing is mathematically correct;
    averaging ratios would not be.

src/components/Canvas/MetaballOverlay.tsx — GPU visualization:
  A single full-coverage plane over the pins' AABB. Fragment shader (highp float
  — required for world coords up to ~10³ and d² up to ~10⁶ which overflow mediump
  ~65504) evaluates all 4 isolated fields per fragment via the Wyvill formula,
  then blends brand colors by relative concentration: green+purple overlap →
  teal-purple mix. Alpha tracks absolute total strength. VIS_THRESHOLD = 0.15
  drops background fragments.
  Pin streaming (improvements C1): pins are no longer passed as flat uniform
  arrays (which hard-capped the scene at 64 pins). They are packed one RGBA float
  texel per pin — rgba = (x, y, radius, typeIndex) — into a THREE.DataTexture
  (RGBAFormat / FloatType, Nearest min+mag filter), TEX_WIDTH = 256 texels/row,
  height grown by row on demand. The shader is GLSL ES 3.0 (glslVersion GLSL3) so
  the field loop can use the runtime bound `uTotalPins`; it decodes texel i at
  uv = ((i%W)+0.5)/W, (floor(i/W)+0.5)/H and samples it. No fixed cap — thousands
  of pins render in one draw call. Pin mutations only rewrite the texture's
  Float32Array and flip needsUpdate (no shader recompile); the texture is grown
  grow-only and disposed on unmount so rapid mutations never leak GPU memory.

src/components/Canvas/IntentConcentrationGrid.tsx — Hover inspection overlay:
  Triggered by showIntentGrid (set when hovering the Intent Pin ribbon button).
  Discretizes the AABB into 56-unit world cells, calls getRegionConcentration per
  cell, renders cell outlines as lineSegments (world space, tracks pan/zoom) and
  % labels as drei Html DOM nodes. Displays only cells with total >= VIS_THRESHOLD.
  Each label shows short codes (D/P/S/L) + rounded percentage, colored by type,
  sorted by dominance. The data is the exact mix the Phase-2 serializer reads.

src/utils/marchingSquares.ts — Generic 16-case marching squares:
  Samples a scalar field over a regular grid, emits line segments per cell via the
  full 16-case lookup table (explicit saddle handling for cases 5 and 10), then
  stitches loose segments into closed rings by endpoint matching (quantized to
  avoid float mismatch). Generic — takes any (x, y) → number field.

src/utils/intentContours.ts — Per-type isoline extraction:
  extractIntentContours(pins) runs marchingSquares INDEPENDENTLY per IntentType
  at INTENT_ISO_LEVEL = 0.15 (= shader VIS_THRESHOLD, so rings align with the
  visible field edge). Returns per-type closed Ring[] arrays. Bounds padded by
  one cell to guarantee rings close at the border.
 
src/io/intentSerialization.ts — Multi-channel LLM payload (Phase 2 prep):
  serializeIntent(graph, pins) → { vertices, regions }
  Every PSLG vertex carries an intentMix { density, pedestrian, sqf, landuse }
  sampled at its point. Every field-boundary region (from extractIntentContours)
  carries the mix sampled at its centroid. Keys are lowercase, values normalized
  0–1. Example:
    { id: "density-region-0", type: "density", positions: [...],
      intentMix: { density: 0.60, pedestrian: 0.40, sqf: 0.0, landuse: 0.0 } }
  Pure data preparation — no network call. Phase 2 wires it to api/generate.ts.


LOCKING ARCHITECTURE
---------------------
LockPolygon is drawn by a marquee drag (LASSO_LOCK tool). Visual: flat,
semi-transparent grey (binary pointInPolygon fill — the feather gradient removed
from the visual for clarity).

lockInfluenceAt(x, y, locks) in geometry/locks.ts: interior distance field.
  0.0 at polygon boundary → 1.0 at depth ≥ featherRadius inside the polygon.
  Multiple locks combined by max (union). Drives the Normalize pipeline (vertex
  delta scaled by 1 - influence) and will gate the Generate pipeline.

Intent Pins are SPATIAL PROMPTS — they do NOT freeze geometry. They mark
programmatic intent. The two-layer system (geometric lock + programmatic intent)
is the precision advantage over prompt-only generation.


NORMALIZATION
--------------
Entry point: user selects strokes with Marquee or Lasso, right-clicks inside the
selection → "Clean up" panel with a strength slider (0–1). Normalization is
ALWAYS selection-scoped and explicitly triggered — geometry never mutates
automatically. ESC cancels and reverts via revertHistory().

Pipeline (src/geometry/mutations/):

  normalizeSelection.ts — computeNormalizeTargets(graph, strokeIds):
    For each selected stroke, resolves its PathPoints to world-space centerline
    points, calls normalizeStroke(), and maps the returned target positions back
    to vertex IDs. Produces two Maps: originals (current positions) and targets
    (fitted positions). Vertices that belong to no fitted stroke keep original =
    target (they don't move). The caller lerps original → target by strength.

  normalize.ts — normalizeStroke(points: Pt[]): Pt[] | null:
    The primitive classifier + fitter. Returns 1:1 target positions or null if
    no confident fit. Classification order (first match wins):

    OPEN STROKE → best-fit straight line
      Uses PCA on the point cloud: builds the 2×2 scatter matrix [Sxx Sxy; Sxy Syy],
      solves for the dominant eigenvector via θ = 0.5·atan2(2·Sxy, Sxx−Syy), finds
      the min/max projection extents, and distributes the n output points uniformly
      along the fitted line segment. H/V snap: if the line angle is within 8°
      (HV_SNAP_RAD = 8π/180 rad) of a cardinal axis, the line is locked exactly
      horizontal or vertical before distributing points.

    CLOSURE TEST (before fitting closed shapes)
      A stroke is treated as closed when its endpoint gap < 20% of total perimeter
      (CLOSE_GAP_FRAC = 0.2) AND it has ≥ 4 unique points.

    CIRCLE (tried before polygons, only when m ≥ 8 points)
      Algebraic least-squares via the Pratt formulation. Reduces to a 3×3 linear
      system over the moments {Sx, Sy, Sxx, Syy, Sxy, Sxz, Syz, Sz}:
        [Sxx Sxy Sx] [A]   [Sxz]
        [Sxy Syy Sy] [B] = [Syz]
        [Sx  Sy  n ] [C]   [Sz ]
      Center = (A/2, B/2), radius = √(C + cx² + cy²). Solved by Gauss-Jordan
      with partial pivoting. Accepted only if RMS radial error / R < 0.18
      (CIRCLE_RESIDUAL_MAX). Each fitted point is projected radially: angle =
      atan2(p.y − cy, p.x − cx), target = (cx + r·cos, cy + r·sin).

    CORNER DETECTION (shared by triangle and rectangle)
      detectCorners() rotates the loop to start at the point farthest from the
      centroid (most likely a salient corner), then runs an augmented RDP on the
      closed loop with ε = 5% of the bounding-box diagonal (CORNER_EPS_FRAC =
      0.05). Returns the sorted indices of dominant corners.

    TRIANGLE (3 detected corners)
      Corner positions are taken directly from the loop at the detected indices.
      Every loop point is then slid to its arc-length-proportional position along
      the triangle edges via polygonTargets(): the perimeter is parameterized 0–1,
      each point's f = cumArc/perimeter is mapped to the nearest inter-corner
      segment, and the point is linearly interpolated between the two bounding
      corner positions (corners snap exactly; intermediate points slide).

    RECTANGLE (4 detected corners)
      fitRectangle() enforces right-angle geometry:
      1. Edge orientations: average the 4 edge angles using the 4× angle trick
         (sum cos(4θ) and sin(4θ), then atan2/4) to get a modulo-90° consensus
         orientation θ and its perpendicular — avoids circular-mean wraparound.
      2. Oriented bounding box: projects all loop points onto the (ux, uy) and
         (vx, vy) axes to find umin/umax/vmin/vmax, yielding four exact corners.
      3. Each detected corner is snapped to its nearest OBB corner by comparing
         its (u,v) projection to the center umid/vmid.
      4. Degenerate check: all 4 OBB corners must be claimed by distinct detected
         corners; returns null otherwise (no fit).
      Points then slide via polygonTargets() as with triangle.

  Lock gating: strength is modulated per vertex by (1 - lockInfluenceAt(v.x, v.y,
  locks)) before application. A vertex at influence 1.0 (hard lock core) does not
  move regardless of strength slider. Feather zone vertices move proportionally.

Improvements needed / known gaps:
  - No multi-stroke fitting (each stroke is fit independently; parallel corridors,
    L-intersections, and T-junctions are not detected across strokes).
  - No ellipse fitting; near-elliptical closed strokes currently fall through to
    null (no fit).
  - Urban morphology extensions (corridor detection, convex polygon generalization,
    greenway smoothing) are designed in the plan but not yet wired to the UI.

PHASE 2 — LLM GENERATE (Deferred)
-----------------------------------
Serialization infrastructure is built and ready (intentSerialization.ts,
lockInfluenceAt, geoScale). The Generate pipeline itself:

  api/generate.ts — Vercel Edge Function proxying Anthropic API
  System prompt encodes: LOCKED (influence 1.0) = fixed anchors,
    TRANSITION (feather zone) = bend/attach, OPEN (influence 0) = free;
    + intentMix spatial matrix per vertex/region
  Returns new vector segments into the PSLG graph (never raster)
  Reviewable layer: Accept merges, Reject discards, Snapshot before merge

The serializer already produces the exact payload format Claude needs.
Phase 2 activation = wire api/generate.ts + swap the Generate tab placeholder.


COORDINATE SYSTEM (for coding agents)
---------------------------------------
- World origin (0,0) = page center; y up; 1 world unit = 1 screen pixel at zoom 1
- Page bounds: x ∈ [-W/2, W/2], y ∈ [-H/2, H/2]
- Export: fx(x) = x + W/2, fy(y) = H/2 - y
- InteractionPlane (useFrame) gives world-space e.point.x/y on every tool event
- Pan: cam.position.x -= dx / cam.zoom; cam.position.y += dy / cam.zoom
- Zoom anchor: preserve cursor world point by adjusting cam.position post-zoom
- getBoundingClientRect() called live on gl.domElement; never stale cached
- Snap radius: SNAP_THRESHOLD_PX / camera.zoom → world units
